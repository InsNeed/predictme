# 第一版缺口

## 写完 PRD 时

这些在写规格时就已经成立，不是实现之后才发现的：

- 教材拆开的是一次决定里的量，没有「会付钱」的效应量。是或否若交给模型，就仍然是模型的判断。
- 5 岁组人数来自维基百科上的人口金字塔。15–59 岁相加是 892376568，公报第五号是 894376020，差 1999452。只能当相对权重。
- 城镇化率是全国一个数。收入和学历没有已核对的边际，不能写成人口比例。
- 特质五档是标准正态的粗切分，不是中国常模。各轴若独立抽取，就丢掉了真实的相关。
- 学习史、框架、情绪、群体回报没有流行率。教材没给这些基数。
- 实呼必须很少，汇总不能叫全国估计。
- 0–14 岁和 75 岁以上不在抽样框里。15–17 岁仍会落在 15–19 岁这一组。
- 姓名不是姓氏频率。
- 当时还没有密钥，也还没打过真实接口。

## 做成应用时改了什么

挡住一条能走通的第一版的，按上面改了：

- 删掉原来手写的 8 个人设和本地规则模板。人口在代码里生成，默认 960 人，年龄和性别跟金字塔的相对大小走，城乡按 63.89% / 36.11%。
- 每个人在发出请求前就写好预期、想要、喜欢、习惯、重算、框架、情绪、签名和一句趋势。趋势句写明不是这一次。想要和喜欢不是同一句。损失框架写成强条件，不写成开关。
- 身份只标记「可能在比较前退出」，不把模型的是或否改写成一定会。
- 请求里列入教材故意不写的说法，代码自己的设定句也不拿它们当依据。测试会扫这些句子。
- 实呼默认 3，上限 8。配置超出这个范围会被截断并在页面说明。本地人口不受这个上限约束。
- 密钥只读 `config/deepseek.local.json`。没有密钥、文件损坏、单个人设失败、接口报错，都停在页面上的状态，不把应用打崩。
- 汇总的分母只算这次实呼里标签一致且解析成功的人，并写明不是全国比例。
- 全量人设写入本地库。界面不另做历史列表，避免第一版变成第二套产品。
- 日志优先写到本机目录。目录拿不到时只留在内存，应用仍然启动。

本机 Dart 是 3.12.2，原分支的 SDK 约束写成 `^3.13.5`，在这台机器上无法解析依赖。已改成 `^3.12.2`，更新的 Dart 仍然可以用。

## 留下的缺口

- 没有打过一次真实的 DeepSeek。`deepseek-flash`、关闭思考模式、JSON 输出，只按当前文档接上。密钥到位后，额度、截断和模型不听话，都还要看一次真跑。
- 3 个人的比例不是人口估计。960 人里大部分从未被问到。
- 模型可以忽略设定。代码发现冲突时不改判，两个都显示。没有外部对照，谈不上准确率。
- 金字塔和公报差约 200 万人。城乡没有分年龄。特质独立，五档不是中国常模。情境各项是均匀摊开，不是测到的流行率，所以「多数冲动点击是低效度」这一点没有被人数体现出来。
- 15–17 岁在抽样框里。0–14 岁和 75 岁以上不在。
- 姓名只是不重复的标签。
- 收入、学历、地区没有放进边际。
- 界面不列出历史，虽然库里留着每次运行。改密钥要重新启动才读得到。
- Web 端没有准备 Drift 需要的 sqlite wasm，这一版以本机桌面和手机为准。
- 原分支上的固定人设流程被换掉了，不再保留那 8 个人的规则回答。
