# Preview 准确率对照

用群像实验室（`preview/`）对 10 个已有公开结局的产品各跑一次。本文件在出结果之前写定，跑完不改阈值、不改档位。

不改 preview 的代码、提示词和页面。只填表、等它自己跑完、再对照。

## 每次只改这三处

页面默认是 60 人、思考关闭、Flash、篇幅标准、重测 15%、温度 1.0、并发 12、预算上限 ¥5、自动报告开着、报告模型 V4 Pro。对照版本 B 关闭。人群、年龄、性别、看到多少信息、评价维度、时间窗（30 天）、参照类基础率，全部保持默认。基础率留空。

相对默认，只动：

- 样本量：100 人
- 思考深度：低
- 跑完后自动生成 AI 解读报告：开（本来就是默认）

预算上限仍是 ¥5。若某次在上限处停住，状态记为未完成，不提高预算重跑。有效回答少于 80 人，也记未完成。

## 填进网站的内容

各篇「填进网站」里的字段才填。评分/口碑一律写「新上架，暂无评分」，避免把后来的口碑交进去。

每篇完整介绍的第一句都是：

> 不要调用你已经知道的这款产品的下载量、收入、评分和后来的结局。只根据眼前这份介绍，以这个人的处境判断。

这句话在完整介绍里。读完介绍的人看得到；看商店页的人只能看到简介开头约 160 字，所以也能看到这句和介绍的开头；只扫一眼的人只看到名字和一句话，看不到这句。系统提示里本来就要求只根据看到的信息作答。知名产品的名字仍可能让模型想起真实口碑。这一点记在偏差里，不为此改提示词。

「不要填进网站」一节里的结局、融资、下载量和关停日期，不进入任何输入框。

## 事先定死的档位

预测用有效回答里「30 天内试用概率」和「30 天内首笔付费概率」的算术平均。用原始均值比较，不先四舍五入。

- **高**：平均试用 ≥ 35，或平均付费 ≥ 12
- **低**：平均试用 < 15，且平均付费 < 5
- **中**：其余

事实档在各篇写死，对照关系是：

| 事实 | 预测应当落在 |
| --- | --- |
| 热门成立 | 高 |
| 普通 | 中 |
| 冷门或失败 | 低 |

**准确率 = 档位对上的个数 / 10。** 未完成的那一格算没对上，仍留在分母里。

方向（另外报告，不并进上面的准确率）：已完成的「热门成立」试用均值，再取平均；已完成的「冷门或失败」同样处理。前者高于后者，记试用方向正确。付费概率用同一做法再记一次。某一档一个都没完成，该方向记为无法计算。
